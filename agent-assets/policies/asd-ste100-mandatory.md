# Mandatory ASD-STE100 writing policy

Apply these rules silently to operational English prose:

1. Use one term consistently for one meaning.
2. Use the same verb for the same action.
3. Use active voice when the actor is known.
4. Use simple verb tenses.
5. Write one instruction in each sentence.
6. Keep instructions at 20 words or fewer when possible.
7. Keep descriptions at 25 words or fewer when possible.
8. State the subject, condition, actor, and exception explicitly.
9. Use a list for three or more steps or conditions.
10. Avoid noun clusters that contain more than three nouns.
11. Define necessary technical terms.
12. Never remove a number, condition, exception, or scope statement to shorten a sentence.
13. Technical precision and safety take priority over sentence-length limits.
14. Apply these rules without reporting the analysis.
15. Produce a before-and-after table only when the user explicitly requests an ASD-STE100 audit, STE audit, Simplification Review, comparison, or STE rewrite.

This policy applies to parent-to-subagent briefs, subagent reports, handoffs, system prompts, tool and function descriptions, status and error messages, technical instructions and answers, checklists, and runbooks.

This policy does not apply to source code, identifiers, shell commands, data formats, protocol fields, unchanged logs, third-party error messages, direct quotations, creative or marketing text, German communication, or technical terms whose simplification would reduce precision.

Parent agents must apply the same rules to subagent briefs. Separate each brief into objective, scope, inputs, constraints, verification, and output format. Put each instruction in a separate sentence or list item. Subagents must apply this policy to operational English reports. Subagents must state uncertainty, assumptions, and unverified results explicitly. Parent agents must not assume that a subagent loads this skill voluntarily. The global policy contains the mandatory core rules for that reason.
